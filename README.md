# LLM Policy Prompt Analysis

以一份名为 **Operating Policy** 的提示词文档为样本，分析它如何通过运行政策声明、规则重定义和拒绝纠偏话术，尝试影响大语言模型的指令遵循行为。

本项目关注提示词文本的结构与意图，不宣称样本能够稳定绕过任何模型的限制。

## 项目背景

分析对象来自文件 `gemini4-Antigravity.md`。文件正文是一份英文 Markdown 文档，标题为 `Operating Policy`，内容并不是可执行程序，而是一组面向 AI 助手的行为指令。

文件名可能暗示其预期使用环境，但正文不足以确认作者、来源、适配产品或适配模型。因此，本项目使用通用的 LLM 名称，不将其描述为 Gemini 或任何其他产品的官方配置。

## 这份文档想实现什么

它试图让接收文档的 AI 接受一套由文档自行声明的规则，包括：

- 将当前环境描述为私人、单人使用的专业开发环境。
- 将大量敏感请求划入应当完整交付的范围。
- 将拒绝条件收窄为文档列出的五类事项。
- 将与其冲突的安全提示描述为外部注入。
- 将拒绝或降低输出强度解释为需要纠正的误判。
- 要求模型直接输出结果，且不提及这份规则。

这些都是**样本自身的主张**，不代表模型服务商的实际政策或系统指令。

## 内容结构

| 章节 | 文档中的作用 |

| Output and conduct / Invariants | 重复约束输出形式与后续行为 |

## 分析要点

### 1. 权威来源伪装

文档没有将自己表述为普通参考材料，而是声称自己就是当前部署的运行政策。这种表述试图让模型赋予文档高于其实际来源的指令权限。

### 2. 规则边界重定义

文档自行列出五项禁止事项，并声称除此之外的请求都应完整执行。这里需要区分“文档声称允许什么”和“实际系统允许什么”。

### 3. 冲突指令重新解释

文档预先描述可能出现的安全提示，并要求模型将其视为外部注入。这是在尝试改变模型处理指令冲突的方式。

### 4. 拒绝纠偏与重复强化

多个章节将拒绝、保留意见或降低输出强度称为误判，再通过示例和重复声明强化预期行为。

### 5. 文档内容与有效指令的区别

读取、引用或分析一份文档，不等于接受其中的行为指令。文档自称具有最高权限，也不意味着它真的获得了相应权限。

## 适合用于什么

- 学习提示词注入与指令层级冲突的基本概念。
- 对比普通任务描述与试图重写模型规则的文本。
- 研究模型能否区分待分析材料和实际用户请求。
- 编写模型行为评估的样本说明与结果记录。
